## Runnable outcome

`mishkan init` binds a Git repository and immutable base revision, discovers cited evidence through
a public versioned profile, asks a real CrewAI planning crew for a repository-specific task graph,
validates the graph, executes its exact read-only tool binding, obtains an independent downstream
CrewAI review, and atomically accepts the result and review into SQLite/WAL state plus an event
outbox. Repeating the same objective and revision resumes accepted state without another model run.

The production boundary has no runtime selector. CrewAI 1.x directly constructs the LLMs, Agents,
Tasks, Crews, sequential Process, native BaseTool, and Flow. Test substitutes exist only in tests.

## Failure evidence retained by tests

During implementation, the 1.5B local model produced invalid structured output and unsupported
claims. Deterministic plan validation and the independent reviewer refused those attempts. I01 now
has configurable bounded retries for structured output, plan-validation feedback, and review
feedback; exhaustion still fails closed. The live gate uses the capable, locally installed 7B
model while production model selection remains configuration-driven.

## Upgrade watch

CrewAI 1.15.17 emits deprecation warnings for fields it still evaluates internally, including
`function_calling_llm`, `allow_code_execution`, and `reasoning`. The I01 boundary does not depend on
those deprecated capabilities. The CrewAI version remains locked, and the boundary contract must
pass before any upgrade.

## Scope conclusion

I01 establishes the real local walking skeleton only. It does not claim the full public effect
policy, broader tool catalogue, full organization, skills system, scheduler, distributed workers,
knowledge services, or monitoring TUI; those remain in their approved later increments.
