## Observed mechanism result

The tested initialization path follows the required lifecycle:

1. CrewAI proposes the repository-specific plan.
2. Deterministic validation resolves an immutable tool-registry snapshot, exact task and reviewer
   bindings, policy decisions, and approvals before accepting plan version 1.1.
3. CrewAI Agents and Tasks receive only `GatewayCrewAITool` instances built from that accepted
   lineage.
4. The fixed capability gateway validates schemas and resolved targets, evaluates public policy,
   resolves credentials late, dispatches the configured adapter, inspects the complete result, and
   persists non-secret decision lineage.
5. Deterministic result verification precedes an independent downstream CrewAI review under a
   different role; final acceptance and outbox persistence remain MISHKAN-owned.

The obsolete I01 direct file tool and registry were removed, so the tested path has one tool path.
Operational target extraction, resource requests, isolation limits, inspection rules, policy
rules, sources, and tool compositions are visible versioned configuration rather than a private
action list.

The bundled catalogue now also exposes `core.process.exec@1` through a runnable native adapter.
It executes an absolute executable with literal arguments and no shell, inherited ambient
environment, expansion, redirection, substitution, or separator interpretation. The invocation
governs the exact argument values as an independent public-policy dimension, the working
directory, explicit environment delta, late credential references, stdin,
timeout, expected exit codes, output preview, resources, and declared effects. Timeout,
cancellation, output overflow, unverified effects, and unenforceable network denial produce
explicit non-success or uncertain results rather than false completion. Complete bounded output is
inspected before only previews, byte counts, and digests enter durable evidence.

These results validate the registry, binding, policy, gateway, and evidence mechanisms only. They
do not validate the current bundled source as the SWE organization catalogue. In particular,
`git.commit`, `git.push`, `deployment.apply`, `release.publish`, and `migration.apply` currently
delegate to an abstract `StatefulBackend`; without a configured runnable adapter and satisfied
availability conditions, they cannot truthfully appear as operational capabilities. The Process
surface does not yet close I02: minimum Artifact support, repository-specific discovery evidence,
and the real CrewAI/Ollama multi-repository gate remain pending.
