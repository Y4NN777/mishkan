## Observed runnable result

The local implementation now runs one loopback-only `mishkand` application authority. Its
versioned command ledger reserves effectful commands durably before dispatch, then accepts the
aggregate revision, event cursor, and result atomically after the effect. Replaying an accepted
UUID returns its original receipt. If the daemon is interrupted after dispatch but before
acceptance, replay returns the durable refused receipt with `automatic_retry: false` and requires
effect reconciliation instead of repeating an unknown effect.

SQLite/WAL metadata is created and upgraded only by explicit Alembic commands. The tested upgrade
recognizes the exact I02 layout, makes a backup, imports retained state, and rejects unknown
schemas. The CLI exposes explicit daemon setup, schema status/upgrade, token rotation, bounded
queries, event follow/export, change-set, terminal, job, and run operations. The synchronous SDK
uses the same authenticated HTTP contracts. All non-health endpoints require the instance token;
the token is atomically stored as a regular `0600` file outside YAML.

Artifacts use authoritative relational manifests and filesystem content-addressed bodies.
Streaming uploads enforce exact offsets, size, digest, and backpressure before publication.
Collections are immutable, working references use compare-and-swap, and retention roots include
collections, holds, and pins. Garbage collection is a distinct plan/apply lifecycle. Missing and
corrupt bodies remain visible under explicit lifecycle states, and event export produces an
atomically replaced JSONL file.

Change sets cover exact `mkdir`, `create`, `write`, `replace`, `patch`, `rewrite`, `move`, `copy`,
and `delete` operations. Preimages and prepared journals precede effects; symlink-containing paths,
stale bases, ambiguous replacements, changed destinations, and concurrent after-states fail
closed. Recovery proves the real after-state before accepting an interrupted operation. Git stage,
commit, push, force-with-lease, and explicit force push remain separate adapters governed by the
public effect policy rather than private action bans.

The daemon supervisor owns real Unix PTYs and managed jobs with process-group identity,
`pid + create_time` verification, cursors, readiness, signals, cancellation, deadlines, settlement,
and immutable output artifacts. A lost PTY is never described as reattached. Secret inspection
preserves cross-chunk state. Fault testing also exposed and corrected a descriptor-ownership bug:
job reader threads now own duplicated pipe descriptors, so delayed stream cleanup cannot close a
descriptor later reused by SQLite.

Runs persist the normative task lifecycle. Dependency release and its acceptance event share one
transaction; duplicate completion is ignored, cancellation is monotone, and interrupted work is
released only after effect reconciliation. Loop conditions use the bounded declarative predicate
DSL; no Python `eval` path exists. CrewAI remains the sole agentic runtime while MISHKAN owns
effects, validation, acceptance, and resume.
